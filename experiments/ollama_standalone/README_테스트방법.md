# DataGuard · Ollama 독립 성능 테스트 v0.1.3

**목적:** 기존 DataGuard 프로젝트(①~⑤)의 코드를 바꾸지 않고, Qwen2.5 로컬 LLM의 보완 후 제안 품질과 실험 근거를 비교합니다. 테스트 파일만 프롬프트로 사용하며 실제 라벨링데이터에 접근하거나 원본을 수정하지 않습니다.

## 설치·실행 (Windows)

1. ZIP 전체를 기존 `data-guard-agent` 폴더 **밖의 별도 폴더**에 압축 해제하세요. 이전 v0.1.2를 사용 중이라면 해당 독립 테스트 폴더의 파일을 **v0.1.3 전체로 교체**하세요.
2. Windows PowerShell에서 압축 해제한 폴더로 이동한 다음 `python .\ollama_test_ui.py`를 실행하거나 `RUN_TEST.cmd`를 더블클릭하세요.
3. `로컬 Ollama 연결 확인`으로 `qwen2.5:7b-instruct` 모델을 확인하세요. Ollama가 설치되지 않았다면 먼저 공식 Windows Ollama 앱을 설치해야 합니다.
4. `선택 사례로 Ollama 실제 호출` 또는 `여러 사례 일괄 테스트`를 클릭하면 각각 CSV와 Excel을 동시에 내려받을 수 있습니다.
5. 모델을 다시 실행하지 않고 과거 CSV를 Excel로 바꾸려면, `예전 결과 CSV 불러오기` → `현재 CSV를 비고 시트 포함 Excel로 변환 (Ollama 재호출 없음)`을 클릭하세요.
6. 담당자가 `수정안 정확성 평가`를 저장하면 **평가 완료 CSV**와 **평가 완료 Excel**이 새 파일로 생성됩니다. 원본 결과는 변경하지 않습니다.

추가 설치 패키지는 필요하지 않습니다. 테스트 GUI에는 Gradio가 필요하며, Excel 파일은 Python 표준 라이브러리로 생성합니다.

## Excel 구조

| 시트 | 내용 |
|---|---|
| `테스트 결과` | 모델 호출 기록, **Ollama 제안**, **Ollama 근거**, Ground Truth 비교용 모범답안, 평가 주체, 수정안 정확성 평가, 소요시간 등 |
| `비고` | 모든 결과 컬럼명의 뜻·작성 주체·주의 사항과 `평가 주체` 및 `수정안 정확성 평가` 각각 세 가지 상태의 정의 |

변경된 표준 CSV/Excel 열: `모범답안_비교용(Ground Truth)` · `자동 키워드 검사(참고용)` · `Ollama 실행 오류`. 기존 CSV의 `모범답안_비교용`, `자동키워드확인`, `오류`도 불러오며, **원본을 건드리지 않고 새 Excel 출력에서 이름을 변환**합니다.

### `평가 주체` 정의

- `미평가`: 사람이 수정안을 평가하지 않았으며 수정안 정확성 평가는 기본적으로 `추가 검토 필요`입니다.
- `참고용 잠정 내용 평가`: 이전 모델 답변을 참고해 붙인 **임시** 검토 의견입니다. 실데이터와 규칙에 대한 확정 평가가 아닙니다.
- `담당자 수동 평가`: 독립 테스트 화면에서 사람이 직접 선택하고 평가 근거를 저장했습니다.

### `수정안 정확성 평가` 정의

- `적절`: 구문규칙과 확인된 오류에 비추어 수정 방향이 합당합니다. **실제 보완 완료를 의미하지 않습니다.**
- `부적절`: 모델 제안이 규칙·경로·원본 상태와 충돌하거나 임의 수정값을 요구합니다.
- `추가 검토 필요`: 적용 규칙, 원본 데이터 또는 승인 기록이 부족해 적절성을 확정할 수 없습니다.

### Ground Truth 주의 사항

`모범답안_비교용(Ground Truth)`은 **평가용 참고 모범답안**이며 Ollama에 입력하거나 미세조정(파인튜닝)에 사용하지 않습니다. 이 파일의 S01~S06 사례는 일부 구문규칙에 기초한 **가상·축약 테스트 사례**이므로, 실데이터를 검증해 확정한 Ground Truth가 아닙니다. 실제 원본/규칙 대조를 거쳐 승인된 경우에만 Case KB의 신뢰 가능한 사례로 사용할 수 있습니다.

## Rule Engine / Correction Agent / Case-Based RAG

- **Rule Engine(결정론적 Python):** 파일의 계층 경로, 자료형, 필수 키, 허용값, 정규식 등 명시된 검증 규칙을 재현합니다. Python을 사용했다고 해서 모든 프로그램이 Rule Engine인 것은 아닙니다.
- **Correction Agent(로컬 Ollama):** 규칙과 실제 오류 근거를 바탕으로 한국어 보완 후 지시문을 **제안**합니다. 문장의 의미 정확성은 별도로 검증해야 합니다.
- **Case-Based RAG(추후 추가):** 승인된 실제 보완 사례만 검색 대상으로 구축하고, 규칙으로 바로 해결하기 어려운 오류에 한해 유사 사례를 모델에 전달하는 구조입니다. **v0.1.3에는 실제 검색형 Case KB가 구현되지 않았습니다.** 향후 실험에서는 평가에 사용하는 사례와 검색용 사례를 분리해야 합니다.

## 검증 방법 및 데이터 보호

- 코드 단위 테스트: `python test_local_only.py` (9건)
- 로컬 Ollama 연결·실제 모델 실행 및 Windows Gradio UI는 사용자 PC에서 확인해야 합니다.
- 모델이 호출 성공했어도 정확한 보완안을 제안했다는 의미는 아닙니다.
- `자동 키워드 검사(참고용)`은 단어 포함 여부만 판단합니다. 의미 오류는 **수정안 정확성 평가**에 기재합니다.
- 모델 오류를 의미하는 `부적절`과 API 예외를 의미하는 `Ollama 실행 오류`는 별개입니다.
- 실제 회사 데이터나 결과 CSV/XLSX를 회사 승인 없이 외부 저장소·GitHub에 공개하지 마세요.
